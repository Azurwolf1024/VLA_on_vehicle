# 仿真场景

## 1. 几何（甲板系，单位 m）

```
        +y (左舷)
         ↑            ┌─────┐ ← 垃圾舱 0.15×0.13 内腔, 深 0.10
         │            │ bin │   中心 (0.32, 0.06)
         │            └─────┘
         │        █ 机械臂基座 (0,0)
   ──────┼────────────────────────→ +x (船头)
         │  ═══════════   ← -y 舷墙上的**作业口** (半宽 0.22), 舷墙在此断开
         │
    ≈≈≈ ○   ●   ≈≈≈    ← 垃圾漂在**船舷外的水面上**
         │   水面 z = -0.12
```

| 项 | 值 | 说明 |
|---|---|---|
| 甲板 | 半尺寸 (0.48, 0.36)，厚 0.03 | 绕垃圾舱开孔后由 4 块板拼成 |
| 干舷 | 甲板面距水面 **0.12** | 低干舷是这条任务成立的前提（见 §2） |
| 船体 | 半尺寸 (0.60, 0.38) | 同样开孔，舱底因此是真正的凹坑 |
| 垃圾舱内腔 | 0.15 × 0.13，深 0.10 | 舱底 z = −0.10；中心 (0.32, 0.06) |
| 舷墙 | 高 0.05 的薄板 | **作业侧断开 0.44 m**，臂从这里伸出去 |
| 机械臂 | NERO 7-DOF，工具长 0.105 | 见上游 `veh_arm` |
| 夹爪 | 二指平行，最大开口 84 mm | 指垫 24×12×73 mm，摩擦 2.0 |
| 水面 | z = −0.12，**纯视觉** | 关掉碰撞（见 §5.1） |
| 支撑面 | z = −0.12，位掩码 `contype=16` | **只有垃圾看得见**，让垃圾"浮"在水面上 |

垃圾舱为什么在 (0.32, 0.06) 而不是甲板另一头：打捞口就在 −y 舷侧，
把桶放在同一侧，"捞起来 → 转身 → 投"路径最短。早期放在对角 (0.26, 0.26) 时，
单回合要横跨 0.72 m 甲板（97 步），而且船头相机必须同时包住对角两端，
垃圾在 160² 画面里只有 6 px；改到同侧后 85 步、8 px，成功率不变。

## 2. 可达域：为什么是"舷外 0.54 m 以内"

工具朝下、**偏航跟随目标方位角**（`_tcp_R_target`），从 READY 位形解 IK：

| r \ z | +0.02 | −0.06 | −0.10 | −0.14 | −0.18 |
|---|---|---|---|---|---|
| 0.30 | ✓ | ✓ | ✓ | ✓ | 5.3 |
| 0.34 | ✓ | ✓ | ✓ | ✓ | 2.6 |
| 0.38–0.46 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 0.50 | ✓ | ✓ | ✓ | ✓ | 5.9 |
| 0.54 | ✓ | ✓ | ✓ | ✓ | 32 |
| 0.56 | ✓ | ✓ | 2.5 | 19 | 58 |
| 0.58 | 4.5 | 6.4 | 12 | 45 | 83 |

（✓ = 位置误差 <2 mm；数字是残余误差，单位 mm。z 为甲板系高度，水面在 −0.12。）

两条边界值得记住：

1. **r 上限 ≈ 0.55 m**：不是臂长不够（伸展可达 0.72 m），而是腕部 J6/J7 到了限位。
   早期用恒定 yaw=0 时更早失效：r=0.45 处位置误差就有 29 mm —— 也就是"够不着"。
   让偏航跟随方位角后同一目标到 0.5 mm，J6/J7 余量 >0.6 rad。
2. **方位角 ±160° 之后失效**：实测 θ=−160° 时间误差 158 mm。所以撒布区取
   θ ∈ [−112°, −68°]（−90° 即 −y 正横），偏出这一带就要重算。

`tests/test_env.py::TestWorkspace` 会遍历每回合的抓取点与垃圾舱中心，替你把关。

## 3. 垃圾

| key | 几何 | 尺寸 | 质量 | 中文名 |
|---|---|---|---|---|
| `can` | 圆柱 | r 0.028, h 0.10 | 0.08 kg | 易拉罐 |
| `cube` | 长方体 | 0.056 × 0.056 × 0.064 | 0.09 kg | 方块 |
| `carton` | 长方体 | 0.10 × 0.06 × 0.04 | 0.07 kg | 纸箱 |
| `bottle` | 圆柱 | r 0.022, h 0.124 | 0.06 kg | 水瓶 |

每回合随机挑 3 件，**形状与颜色都互不相同**，保证语言指令在场景里永远唯一可解。

撒布区是**船舷外的一段水面极坐标**：r ∈ [0.435, 0.55]，θ ∈ [−112°, −68°]，
且强制落在船体轮廓之外 35 mm。垃圾按"躺在世界水平面上"摆放（甲板系 z = −0.12 + 半高），
所以船的横摇会让它们在**甲板系里漂移** —— 这正是本任务区别于"在甲板上捡"的地方。

**初始朝向**让长方体窄边正对指爪：物体局部 y 轴 ∥ 工具 y 轴（`yaw = atan2(y, x)`）。
这条曾经错过两次（先差 90°、再差 29°），后果都是 100 mm 宽的纸箱被 84 mm 的爪子
压进两侧各 8 mm，下探卡死。正确关系来自 `topdown_rotation` 的定义
`y_t = (sin yaw, −cos yaw)`，**不是** `(cos, sin)`。

没有球体：球在倾斜甲板上会一直滚（1 s 滚走 12 cm）。这是任务定义问题，不是策略问题。

## 4. 载具运动

直接复用上游 `veh_arm.platform.vehicle.VehicleMotion`：

* `sea` / `road` / `air` / `rail` / `static` 五种谱，`scale` 是幅值倍数；
* 默认 `sea, scale=0.35`（有义波高约 0.12 m 的近海工况，峰值线速度 ~0.11 m/s）；
* vessel 是 **mocap 体**：每帧写 `mocap_pos/mocap_quat`，质量视为无限大，
  接触力与机械臂的反作用都推不动它。
* 代价：mocap 体在 MuJoCo 里速度恒为零，臂的动力学感受不到基座速度项
  （上游模型里的 `J_B·V_B`）。海况 0.1 m/s 量级下对应毫米级误差，
  比"基座自由落体"（见 §5.2）小两个数量级。

**回合从"船体接近水平"的相位开始**（`level_start`）：在 40 s 时间窗里扫 `(roll, pitch)`，
取最平的时刻作为 t₀。这只影响初始条件（垃圾摆在水平甲板上，不会一开局就滑走），
回合中该晃还是晃 —— 实测 0.35 档下 1 s 内物体漂移 < 0.1 mm。

## 5. 三个必须记住的坑（都踩过）

### 5.1 水面平面不能参与碰撞

船体吃水线以下本来就在水面里。让 `plane` 有 `contype` 时，求解器每一步都会给 vessel
一个向上的巨大速度冲量（实测 qvel_z ≈ +0.08 m/s／步）；甲板在水下"抖"，
再通过摩擦把垃圾拖着走 —— 表现是"回合一开始物体就漂了 4 cm"，
而所有打印出来的甲板位姿都是静止的，极难定位。

### 5.2 vessel 不能是自由体（这条最贵）

最早 vessel 挂 `<freejoint>`，每帧把解析位姿写回 `qpos/qvel`，看上去船是"钉住"的。
但船在**每一步内部**都是自由落体：实测 0.1 s 掉 4.9 cm，只是被下一次覆写掩盖了。
后果是机械臂的基座一直在"下坠"——

* 位置伺服靠硬刚度硬扛，几乎看不出来（所以这条隐藏了很久）；
* 一旦换成上游 TSID（它的全部前提是"基座运动由外部给定"），立刻崩：
  给 `τ = g(q)` 做重力补偿，臂直接掉 4.34 rad，观感是"力矩环怎么调都不稳"。

诊断方法：**开环**给 `τ = M q̈* + H`，看 MuJoCo 实际返回的 `qacc` 是否等于 `q̈*`。
不等就说明 plant 与模型不是同一个对象，问题在场景而不是控制器。改成 mocap 后
同一实验的漂移 4.34 rad → 0.054 rad（剩下的是关节阻尼与干摩擦）。

### 5.3 位置伺服 + 软接触抓不住轻物体

用纯接触摩擦（`grasp_mode="contact"`）时，指垫与物体之间会**持续滑移**
（实测一条提升动作里相对滑移 40–180 mm，物体最后掉出来）。诊断结论：

* 法向力正常（7 N/指）、摩擦系数正常（μ=2.0）、接触维数正常（condim=4）；
* 换积分器 / 提高迭代数 / 提高 impratio / 加大指力，滑移量**一字不变**；
* 同一套参数下"盒子在 30° 斜面上"是稳的 —— 说明不是摩擦模型坏了，
  而是"轻物体被重手夹住"这个质量比下的约束求解病态。

第一版因此用**运动学吸附**（`grasp_mode="attach"`，默认）：闭合到位即把物体
钉在工具上，张开即释放。释放后的下落、落点、碰撞仍是真物理。
需要纯接触物理时把 `grasp_mode` 设成 `"contact"`，但那套参数还需要调。

## 6. 时序与性能

| 层 | 频率 | 说明 |
|---|---|---|
| 物理 | 500 Hz | `dt=0.002`, `implicitfast` |
| 内环 `pos` | 100 Hz | 每个内环步重解一次 IK（热启动 3 次迭代） |
| 内环 `tsid` | 500 Hz | 每个物理步解一次 QP（上游解析模型） |
| 决策 | 10 Hz | 两张图渲染 + 记录 |

单条回合（约 88 个决策步）实测：采集 **12 s/条**（含建模 0.5 s、静置 0.6 s、渲染）。
`tsid` 另加 7–11 s（500 Hz × 每次 `state_terms` 0.43 ms）。
**采集用 `pos`，`tsid` 是用来验证动力学补偿的**，不是数据来源。

注意 v0.2 的 `pos` 比 v0.1 慢：舷外任务里目标在甲板系里**持续变化**（船在动，
物体在水面），所以不能像早期那样"每个决策步解一次 + 关节插值"，改成
每个内环步重解（10 次/决策步）。插值会引入半步滞后，在 0.5 m 的伸展上就是几十毫米。

## 7. 相机怎么摆：用投影量，不要靠眼看

相机的两个参数（位置、fovy）决定了"任务相关的东西在画面里占几像素"，
这件事可以算，不必反复出图看。

做法：把关心的 3D 点（TCP、指垫中心、物体中心、垃圾舱中心）投到像素坐标，
再对**包围盒的 8 个角**求屏幕上的覆盖面积。两次实测把它变成了可判定的问题：

| 候选 | 夹爪占屏（包围盒） | 结论 |
|---|---|---|
| 工具系 `(0.05, 0, 0.02)` | 36% | 太大 |
| 工具系 `(0.10, 0, 0.05)` | 12% | 采用（fovy 80°） |
| 工具系 `(0, −0.06, 0)` | 43% | 沿 y 侧移落在指垫背面 |

但**投影只回答"挡住多少"，不回答"挡住的是谁"**。有一轮把 `(0.08, 0, 0.04)` 出图，
画面被一整块黄色占满，看起来像指垫挡住了 —— 实际把 pad 染成品红、palm 染成红色后
才看清：那块黄色是**要抓的黄色纸箱**，夹爪在两侧好好的。

所以现在的流程是：**先给几何体换醒目颜色确认遮挡源，再调参数**。

顺带记住两条几何事实（它们决定了相机能不能看得见）：

* 掌部是一块 60×52 mm 的板，相机放在它后面就什么都看不见；
* 指垫 24×12×73 mm，从掌部一直伸到离 TCP 只有 2 cm —— 侧面看就是一根长条。
