# 路线图

分阶段，每阶段的完成标准都是**可测的数字**，不是"能跑"。

## v0.1 框架（当前）

- [x] MuJoCo 场景：载具甲板 + 舷侧作业口 + 舷外水面漂浮垃圾 + 内置垃圾舱 + NERO + 双相机
- [x] 由 `ArmSpec` 生成 MJCF，并用测试保证与上游 FK 逐点一致（1e-7）
- [x] 10 Hz 决策 / 100 Hz 逆解 / 500 Hz 物理三级时序
- [x] 脚本专家（分阶段 + 位移限幅）+ 回合录制 + 训练/评测脚本
- [x] 行为克隆基线（双相机 + 字符级指令 + 本体感觉 → 4 维动作）
- [x] 24 条单元测试（含一条跑完整示范的端到端测试）

**完成标准**：专家在静止 / 0.35 / 1.0 三档海况下均 ≥90%（实测 30/30，
`deck` 与 `world` 两种参考系全通过）。

## v0.2 动作与任务

- [ ] 动作扩到 6 维（+ 腕部 yaw / 俯仰增量），俯仰用于侧向抓取
- [ ] action chunk（一次预测 k 步）+ 时序集成，对齐预训练 VLA 的常见输出
- [ ] 多目标回合（"把三件都收进舱"），`target_index` 变成序列
- [ ] 评测拆成**抓取成功率 / 投放成功率 / 端到端成功率**三个指标

**完成标准**：BC 在 100 条示范上端到端成功率 ≥50%。

v0.1 的实测基线（20 条示范 / 15 epoch / 96²）：训练侧 val L1 0.17、夹爪准确率 96%，
**闭环 0/6**。失败模式是"朝物体走，但在离物体 7.7 cm 处就闭爪，之后再不张开" ——
策略拟合了示范的时间规律而不是视觉伺服关系。这是单步 BC 的协变量漂移，
上面三项改动正是针对它。

## v0.3 让载具运动真正起作用

**任务本身已经搬到世界系了**（v0.2 的改动）：垃圾漂在船舷外的水面上，
不再躺在甲板上。这一步把"船摇"从感知问题变成了控制问题 ——
物体在世界系固定，而机械臂的基座在晃，不补偿就抓不准。

实测（sea 0.35 / 1.0，抓取瞬间 TCP 相对物体中心的水平偏差）：

| frame | sea 0 | sea 0.35 | sea 1.0 | 平均步数（sea 1.0） |
|---|---|---|---|---|
| `deck`（目标随甲板动） | 0.1 mm | 1.2 mm | 2.6 mm | 89 |
| `world`（目标钉在世界） | 0.2 mm | 0.5 mm | **1.0 mm** | 113 |

成功率两者都是全通过（30/30），所以差别只在"抓得准不准"和"快不快"上体现。
2.6 倍的偏差差距就是基座运动补偿的实际收益；27% 的步数代价是补偿本身的成本。

还差：

- [x] 把 `veh_arm` 的 TSID 力矩环接进 MuJoCo（`control/tsid.py`，`env.control_mode="tsid"`）
      顺带验证了上游解析模型与 MuJoCo 是同一份模型（M/H/J 误差 1e-6 量级）
- [x] 世界系参考系（`env.frame="world"`）与"船摇抑制"量化指标
      （零动作保持 3 s：TCP 世界游走 31.6 mm → 1.1 mm）
- [x] 世界系任务变体：垃圾漂在**舷外水面**上（世界系固定），必须抵抗船摇才能夹准
- [x] **目标随载具运动**（`target_motion` × `surface_source`）：`pinned`/`surface`/`deck`
      × `vehicle`/`independent`，船载、车载、岸边共用一套代码。
      第一版把波面错接成船体升沉（实测两者**反相 151°**、幅值 0.34 倍），修正后结论反转：
      误差主要来自**基座运动** —— 目标自己晃 291 mm 只贡献 0.2 mm，
      同样的海面搬上船就变成 15.6 mm
- [x] 车载 / 岸边工况：`vehicle_mounted`（停稳）、`vehicle_road`（B 级路面）、
      `shore_side`（车停码头、夹海里的）。车的角运动比船小 5–11 倍
- [x] 机械臂视觉换成上游真实 NERO 网格（20 万面），两档视觉由测试守住"同一个被控对象"
- [ ] **`sea_surface` + sea 1.0 已经踩到 `max_decisions=170` 上限**（五个回合里
      三个是 167–169 步）。要么提升动作效率（action chunk / 加大单步位移），
      要么按海况自适应放宽上限 —— 否则"成功率 100%"只是海况还没再高一档
- [ ] `surface` 档的支撑面随波移动（现在是世界固定平面，物体每步会短暂穿透，
      位置不受影响但 `qvel` 被污染）
- [ ] 投放侧的世界系变体：把垃圾舱换成岸上/水面上的固定点（桶目前还在甲板上）
- [ ] 消融：`compensate_base=False` 与开/关，在世界系任务上的成功率差异
      （对应上游论文的坐标系代价梯度）
- [ ] 海况梯度上画出 BC 成功率曲线（0 / 0.35 / 0.7 / 1.0）

**进展**（见 `docs/control.md`）：内环已接通；任务已搬到世界系并量化出
"抓取偏差 3 倍"这个收益。剩下的消融还没做：`compensate_base=False`
（上游的 ignore-coupling 基线）在同一任务上的成功率差异。

**完成标准**：在 world 系变体上，开/不开基座前馈的成功率出现显著差异。
目前的量是**精度差**（2.6 mm vs 1.0 mm）而不是成功率差 —— 因为内环够硬，
3 mm 还没到"抓不住"的程度（夹爪开口 84 mm，物体 40–100 mm）。
要让成功率也分出胜负，得把海况再放大，或者把物体换成更难夹的形状。

## v0.4 预训练 VLA 与实机

- [ ] 接一个开源 VLA（SmolVLA / OpenVLA），动作头投影到本项目 4 维动作
- [ ] 相机域对齐：把全局相机换成"桅杆正视"以接近公开数据集视角，量化域差距
- [ ] 真机桥：替换 `PickPlaceEnv.step()` 为 NERO 驱动 + 真实相机（`veh_arm_ctl` 已有硬件抽象）
- [ ] 实船/实车试验：静止 → 系泊 → 低速航行

**完成标准**：实机上完成 ≥20 次连续抓放，记录成功率与失败模式分布。

## 明确不做

* 多臂协同、灵巧手、柔顺装配：与"载具上的抓放"主线无关。
* 用仿真数据直接声称实机性能：`docs/data.md` 的域差距必须先量化。
