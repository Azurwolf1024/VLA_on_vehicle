# 路线图

分阶段，每阶段的完成标准都是**可测的数字**，不是"能跑"。

## v0.1 框架（当前）

- [x] MuJoCo 场景：载具甲板 + 内置垃圾舱 + NERO + 双相机 + 4 类垃圾
- [x] 由 `ArmSpec` 生成 MJCF，并用测试保证与上游 FK 逐点一致（1e-7）
- [x] 10 Hz 决策 / 100 Hz 逆解 / 500 Hz 物理三级时序
- [x] 脚本专家（分阶段 + 位移限幅）+ 回合录制 + 训练/评测脚本
- [x] 行为克隆基线（双相机 + 字符级指令 + 本体感觉 → 4 维动作）
- [x] 17 条单元测试（含一条跑完整示范的端到端测试）

**完成标准**：专家在静止 / 0.35 / 1.0 三档海况下均 ≥90%（实测 24/24）。

## v0.2 动作与任务

- [ ] 动作扩到 6 维（+ 腕部 yaw / 俯仰增量），俯仰用于侧向抓取
- [ ] action chunk（一次预测 k 步）+ 时序集成，对齐预训练 VLA 的常见输出
- [ ] 多目标回合（"把三件都收进舱"），`target_index` 变成序列
- [ ] 评测拆成**抓取成功率 / 投放成功率 / 端到端成功率**三个指标

**完成标准**：BC 在 100 条示范上端到端成功率 ≥50%。

v0.1 的实测基线（20 条示范 / 15 epoch / 96²）：训练侧 val L1 0.17、夹爪准确率 96%，
**闭环 0/6**。失败模式是"朝物体走，但在离物体 7.7 cm 处就闭爪，之后再不张开" ——
策略拟合了示范的时间规律而不是视觉伺服关系。这是单步 BC 的协变量漂移，
上面三项改动正是针对它。

## v0.3 让载具运动真正起作用

v0.1 的诚实结论：**专家对海况不敏感**（100% / 100% / 100%）。
原因是任务写在甲板系 + 位置伺服很硬，船的运动会通过关节目标自动抵消。
所以现阶段"载具"主要影响**感知**（画面在晃、物体在动），而不是控制。

要把它变成控制问题，需要：

- [x] 把 `veh_arm` 的 TSID 力矩环接进 MuJoCo（`control/tsid.py`，`env.control_mode="tsid"`）
      顺带验证了上游解析模型与 MuJoCo 是同一份模型（M/H/J 误差 1e-6 量级）
- [x] 世界系参考系（`env.frame="world"`）与"船摇抑制"量化指标
      （零动作保持 3 s：TCP 世界游走 31.6 mm → 1.1 mm）
- [ ] 世界系任务变体：把垃圾舱换成"岸上/水面上的固定点"，必须抵抗船摇才能投放
- [ ] 消融：`compensate_base=False` 与开/关，在世界系任务上的成功率差异
      （对应上游论文的坐标系代价梯度）
- [ ] 海况梯度上画出 BC 成功率曲线（0 / 0.35 / 0.7 / 1.0）

**进展**（见 `docs/control.md`）：内环已接通且能在三档海况下完成全部 4/4 回合，
但"把载具变成控制问题"还差最后一步 —— 任务本身仍然定义在甲板系，
所以船摇被目标一起带走了。世界系定点目前只是**能力演示**，不是任务配置。

**完成标准**：在 world 系变体上，开/不开基座前馈的成功率出现显著差异。

## v0.4 预训练 VLA 与实机

- [ ] 接一个开源 VLA（SmolVLA / OpenVLA），动作头投影到本项目 4 维动作
- [ ] 相机域对齐：把全局相机换成"桅杆正视"以接近公开数据集视角，量化域差距
- [ ] 真机桥：替换 `PickPlaceEnv.step()` 为 NERO 驱动 + 真实相机（`veh_arm_ctl` 已有硬件抽象）
- [ ] 实船/实车试验：静止 → 系泊 → 低速航行

**完成标准**：实机上完成 ≥20 次连续抓放，记录成功率与失败模式分布。

## 明确不做

* 多臂协同、灵巧手、柔顺装配：与"载具上的抓放"主线无关。
* 用仿真数据直接声称实机性能：`docs/data.md` 的域差距必须先量化。
