# 仿真场景

## 1. 几何（甲板系，单位 m）

```
        +y (左舷)
         ↑
         │      ┌──────────────┐  ← 垃圾舱 0.15 × 0.13 内腔, 深 0.12
         │      │   bin (…)   │     中心 (0.26, 0.26)
         │      └──────────────┘
         │   ○        ●           ← 垃圾: 极坐标 r∈[0.31,0.39], |θ|≤55°
         │        ╱
         │      █ 机械臂基座 (0,0)
         └────────────────────────→ +x (船头)
             甲板 0.96 × 0.72, 距水面 0.30
```

| 项 | 值 | 说明 |
|---|---|---|
| 甲板 | 半尺寸 (0.48, 0.36)，厚 0.03 | 绕垃圾舱开孔后由 4 块板拼成 |
| 船体 | 半尺寸 (0.62, 0.38, 0.15) | 同样开孔，舱底因此是真正的凹坑 |
| 垃圾舱内腔 | 0.15 × 0.13，深 0.12 | 舱底 z = −0.12 |
| 舷墙 | 高 0.05 的薄板 | 挡住垃圾、给视觉边界 |
| 机械臂 | NERO 7-DOF，工具长 0.105 | 见 `vehicle_arm` 上游模型 |
| 夹爪 | 二指平行，最大开口 84 mm | 指垫长 73 mm，摩擦 2.0 |
| 腕部相机 | 掌侧外挂 `(0,−0.042,0.008)`，内倾 18°，fovy 80° | 同轴装法在夹持时会被物体糊满 |
| 水面 | z = 0，**纯视觉** | 关掉碰撞（见 §5） |

## 2. 为什么工作空间是**环形**的

工具必须竖直朝下时，肘关节的限位会把"太靠近基座"的点排除掉。实测可达域：

| r \ z | 0.01 | 0.05 | 0.10 | 0.15 | 0.20 | 0.30 |
|---|---|---|---|---|---|---|
| 0.16 | ✗ 225 | ✗ 205 | ✗ 156 | ✗ 104 | ✗ 49 | ✓ |
| 0.20 | ✗ 157 | ✗ 149 | ✗ 108 | ✗ 62 | ✗ 13 | ✓ |
| 0.24 | ✗ 81 | ✗ 71 | ✗ 46 | ✗ 11 | ✓ | ✓ |
| 0.28 | ~9 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 0.32–0.48 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

（✓ 表示 IK 收敛到 <6 mm；数字是该点的残余位置误差，单位 mm。）

所以垃圾撒布内径不能小于 0.31 m、垃圾舱也必须放在 r≈0.37 m 处。
这条限制不是调出来的，是 NERO 的肘限位 [−1.01, 2.14] rad 决定的；
换臂/换工具长度后必须重算，`tests/test_env.py::TestWorkspace` 会替你把关。

## 3. 垃圾

| key | 几何 | 尺寸 | 质量 | 中文名 |
|---|---|---|---|---|
| `can` | 圆柱 | r 0.028, h 0.10 | 0.08 kg | 易拉罐 |
| `cube` | 长方体 | 0.056 × 0.056 × 0.064 | 0.09 kg | 方块 |
| `carton` | 长方体 | 0.10 × 0.06 × 0.04 | 0.07 kg | 纸箱 |
| `bottle` | 圆柱 | r 0.022, h 0.124 | 0.06 kg | 水瓶 |

每回合随机挑 3 件，**形状与颜色都互不相同**（3 种颜色从 4 色里抽），
保证语言指令在场景里永远唯一可解。

没有球体：球在倾斜甲板上的滚动几乎没有静摩擦下限，实测 1 s 滚走 12 cm，
十几次下来必然滚到舷边。这是任务定义问题，不是策略问题。

**初始朝向**与夹爪开合方向对齐（±10° 抖动）。夹爪最大开口 84 mm，
长方体若随机偏航 45°，投影宽度 (a+b)/√2 可以超过 84 mm，爪子会压在物体顶上"抓不下去"。

## 4. 载具运动

直接复用上游 `veh_arm.platform.vehicle.VehicleMotion`：

* `sea` / `road` / `air` / `rail` / `static` 五种谱，`scale` 是幅值倍数；
* 默认 `sea, scale=0.35`（有义波高约 0.12 m 的近海工况，峰值线速度 ~0.11 m/s）；
* 每帧写入 vessel 的 qpos/qvel，作为**运动学平台**（接触力不反推船）。

**回合从"船体接近水平"的相位开始**（`level_start`）：在 40 s 时间窗里扫 `(roll, pitch)`，
取最平的时刻作为 t₀。这只影响初始条件（垃圾摆在水平甲板上，不会一开局就滑走），
回合中该晃还是晃 —— 实测 0.35 档下 1 s 内物体漂移 < 0.1 mm。

## 5. 两个必须记住的坑（都踩过）

### 5.1 水面平面不能参与碰撞

船体吃水线以下本来就在水面里。让 `plane` 有 `contype` 时，求解器每一步都会给 vessel
一个向上的巨大速度冲量（实测 qvel_z ≈ +0.08 m/s／步）；甲板在水下"抖"，
再通过摩擦把垃圾拖着走 —— 表现是"回合一开始物体就漂了 4 cm"，
而所有打印出来的甲板位姿都是静止的，极难定位。

### 5.2 位置伺服 + 软接触抓不住轻物体

用纯接触摩擦（`grasp_mode="contact"`）时，指垫与物体之间会**持续滑移**
（实测一条提升动作里相对滑移 40–180 mm，物体最后掉出来）。诊断结论：

* 法向力正常（7 N/指）、摩擦系数正常（μ=2.0）、接触维数正常（condim=4）；
* 换积分器 / 提高迭代数 / 提高 impratio / 加大指力，滑移量**一字不变**；
* 同一套参数下"盒子在 30° 斜面上"是稳的 —— 说明不是摩擦模型坏了，
  而是"轻物体被重手夹住"这个质量比下的约束求解病态。

第一版因此用**运动学吸附**（`grasp_mode="attach"`，默认）：闭合到位即把物体
钉在工具上，张开即释放。释放后的下落、落点、碰撞仍是真物理。
需要纯接触物理时把 `grasp_mode` 设成 `"contact"`，但那套参数还需要调。

## 6. 时序与性能

| 层 | 频率 | 说明 |
|---|---|---|
| 物理 | 500 Hz | `dt=0.002`, `implicitfast` |
| 内环 | 100 Hz | 关节目标线性插值 |
| 决策 | 10 Hz | 逆解一次 + 两张图渲染 |

单条回合（约 65 个决策步，6.5 s 仿真时间）实测 ≈ 3.5–4 s（含建模 + 静置 + 渲染 2×160²）。
其中建模 0.5 s、静置 0.6 s。批量采集时把 `rebuild_each_episode` 打开才有随机化，
关掉可以省建模时间但同一批数据会共用一套物体形状/颜色。
