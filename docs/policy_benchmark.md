# 三条抓取路线的同条件对比

传统 CV / 视觉伺服 / 学习式策略，在**同一批回合**上跑一遍，看误差到底来自哪里。

```
python scripts/bench_policies.py --episodes 5 --seas 0 0.35 1.0 \
       --policies expert cv pbvs bc --ckpt runs/bc/policy.pt
```

## 1. 结论

| 方法 | 看到什么 | sea 0 静水 | sea 0.35 | sea 1.0 恶劣 | 平均步数 |
|---|---|---|---|---|---|
| `expert`（上界，读真值） | 甲板系真值位姿 | 5/5 · **0.2 mm** | 5/5 · 1.2 mm | 5/5 · 2.5 mm | 88 |
| `cv`（检测式，开环） | 颜色 + 标定 + 类半高先验 | 5/5 · 9.2 mm | 5/5 · 10.9 mm | 5/5 · **14.6 mm** | 89 |
| `pbvs`（每步闭环） | 同上，但每步重测 | 5/5 · **7.0 mm** | 5/5 · **9.9 mm** | 5/5 · 19.3 mm | 90 |
| `bc`（学习式，单步） | 只有像素 + 本体感觉 | 1/5 · 22.2 mm | 1/5 · 28.0 mm | 3/5 · 29.8 mm | 155 |
| `bc`（学习式，chunk=8） | 同上，一次出 8 步 | 1/5 · 21.7 mm | 0/5 · 37.8 mm | 0/5 · 35.2 mm | 170 |

误差是**抓取瞬间 TCP 相对物体中心的水平偏差**，5 个种子。成功率是硬指标，误差只在成功的回合里有意义。

BC 那两行的 5 回合样本太小（1/5 与 3/5 的差别只是运气），所以单独在 sea 0.35 上跑了
**20 个回合**：**3/20 = 15%**，误差 30.2 mm、平均 160 步。后面所有关于 BC 的判断都以这个
20 回合的数字为准，5 回合的列只用来说明"同一批回合上谁高谁低"。

三句话：

1. **传统 CV 已经很强**。颜色 + 一个标定平面 + 一个类半高先验，9–15 mm、100% 成功。
   在这个场景里"用深度学习"没有精度上的理由。
2. **闭环没有赢**。PBVS 在静水/中等海况略好（7.0/9.9 vs 9.2/10.9），恶劣海况反而更差
   （19.3 vs 14.6）。原因见 §3，是几何与遮挡，不是调参。
3. **学习式差一个数量级**。单步 BC **15%（3/20）**、误差 30 mm；
   naive action chunk 不但没救回来，还更差（§4）。

## 2. 对比纪律

三种方法必须看到**同样的观测**、用**同样的动作**、跑**同样的回合**：

* 同一个 `Obs`：两张 160×160 图 + 关节 + TCP + 夹爪 + 指令；
* 同一个 4 维动作 `[dx,dy,dz,g]`（甲板系 TCP 增量 × 2 cm + 夹爪 0/1）；
* 同一批 seed、同一档海况、同一个成功判据（物体落在垃圾舱内且已释放）。

**唯一允许的差别是"怎么把眼睛变成动作"**。所以 `expert` 的 0.2 mm 不是"算法好"，
而是"它作弊读真值"——它的作用是给出**这条任务在物理上能做到多准**的上界。

`cv` / `pbvs` 的目标属性（颜色、形状）都从**指令文本**解析，不读真值：

```
"把黄色易拉罐捡起来放进垃圾舱"  ->  color=yellow, shape=can  ->  half_height=0.035
```

这一步没有偷懒，任何真实流水线都得先把语言落到属性上。

## 3. 为什么闭环没赢

### 3.1 遮挡：夹爪下探时必然挡住目标

这是把 PBVS 从 21.5 mm 拉到 19.3 mm 的那一刀，也是整条链路的成败所在。

全局相机在船头，机械臂在目标正上方下降。实测可见面积：

| 伺服步 | 指尖高度 | 目标可见面积 |
|---|---|---|
| 0 | z = +0.024 | 101 px |
| 4 | z = −0.036 | 61 px |
| 7 | z = −0.096 | 40 px |
| 15 | z = −0.116 | 24 px |

面积只剩 1/4，检测到的质心是**残余可见部分**的质心，不是物体中心。照它闭环，
末端被引着往外跑：实测 `tcp.y` 从 −0.490 一路漂到 −0.466，而目标在 −0.500——
偏差从 12 mm 涨到 37 mm。看起来像"伺服发散"，实际是**在追一个假目标**。

修法是**用面积做遮挡门控**：可见面积跌破起始值的 60% 就不再修正横向，只把下降走完。
这就是工业上的"接近后开环下探"。

> `cv` 基线天然免疫这件事——它在悬停时只看一次，之后不再看。
> **不修这一条，闭环就一定输给开环。**

### 3.2 平面高度先验错了，闭环会忠实地追错

反投影需要知道物体在哪个平面上。两条路都用 `plane_z = 水面 + 类半高` 这个**标定值**：

* 船一横摇，真实水面在甲板系里就不是这个高度；
* 误差直接进 `(x, y)`。

`cv` 是开环：这个误差**只进一次**，之后机械臂照着错的点走完。
`pbvs` 是闭环：它每一步都在纠正，但**设定点本身是错的**，于是它更精确地走向那个错点。
闭环消除的是"执行误差"，消除不了"感知系统偏差"。

这解释了为什么海况越大，PBVS 相对 CV 越吃亏（sea 1.0：19.3 vs 14.6）。

### 3.3 曾经想做的 IBVS 在这个几何里不成立

先说清楚：试过，失败过，而且是**几何原因**不是调参。

1. **腕部相机做不了**。腕部相机自动瞄准 TCP，而物体在 TCP 下方 25 mm，
   解析投影落在画面上边缘（v≈0）甚至被裁掉。"把质心拉到画面中心"这个期望位置
   本身不存在。
2. **全局 eye-to-hand 也不行**。改成"目标质心 vs TCP 的图像投影"后像素能收敛到
   1 px，但抓取误差仍有 **25 mm**：斜视单目下，"物体与末端在同一视线上"
   **不等于**"末端在物体正上方"——同一视线穿过不同高度的两个点，xy 差 25 mm 很正常。

所以退回**基于位置**的伺服（PBVS）：每步反投影出甲板系坐标，与末端做位置闭环。
它的对照价值是清楚的：`cv` 每个阶段只测一次就开环执行，PBVS 每一步都在测。

## 4. 学习式为什么差一个数量级

### 4.1 训练侧其实不差

40 条示范（新配色）、3588 帧、160² 双相机、40 epoch：

| | 单步 BC | chunk=8 |
|---|---|---|
| val L1 | **0.081** | 0.111 |
| 夹爪准确率 | 99.4% | — |

模仿学习的**拟合**没问题，问题在闭环。

### 4.2 两种典型崩法

失败的回合不是"走歪了"，而是这两类：

**（a）对准差一截**。seed 0 的轨迹：k=40 时 TCP 已经在目标正上方，闭爪，但
`grasp_err = 23.5 mm`。物体 40–100 mm、夹爪开口 84 mm，23.5 mm 已经抓不住，
之后带着空气去投放，判失败。这是"相似状态对应不同动作"被平均掉的结果。

**（b）冲过头 / 卡在分布外**。seed 2 的轨迹：目标在 `(0.034, −0.444)`，
而 k=40 时 TCP 到了 `(0.083, −0.569)`——**冲过 12.5 cm**。之后 TCK 一路输出
满量程 `(−0.97, −0.58, −0.99)` 却原地不动，170 步耗尽。

这就是协变量漂移：单步 BC 把每一步的小误差当成**新状态**再喂回网络，
一旦离开示范分布，输出的动作就不再有任何保证。

### 4.3 action chunk 反而更差

直觉上"一次预测 k 步"应该减少累积误差。实测相反（sea 0.35：0/5，170/170 步耗尽）。

原因在这个任务的结构：**轨迹在每个阶段边界会突变**（悬停→下降→闭爪→抬起），
而策略不知道自己在哪个阶段，只能从图像和本体感觉隐式推断。
一次承诺 8 步，若边界落在 chunk 中间，接下来 0.8 s 全是错的——
而且它**不会中途纠正**，因为 chunk 的语义就是"照这个执行完"。

真正能用的做法需要两件本项目没有的东西：

* **temporal ensembling**（每步都推理，把多个重叠 chunk 的预测加权），
  计算量 ×k，CPU 上不现实；
* **足够大的数据量**，让模型见过各种阶段边界对齐方式的组合。40 条、3588 帧远不够。

`chunk=1` 的代码路径保留了向后兼容（旧权重照常加载，实测 102 步 / 9.7 mm 不变）。

## 5. 过程中修掉的两个缺陷

两个都不是"调参"，是**场景/代码本身错了**，而且都会让结论失真。

### 5.1 指垫和黄色垃圾同色

指垫原来是 `rgba = (0.95, 0.75, 0.15)`，与黄色垃圾的归一化色度只差 **0.017**。
腕部近景里指垫是上千像素的大块——黄色目标的回合，检测 46 次全部失效。

已改成品红（与四种垃圾色的色度距离都 >0.45）。**代价：`data/demos` 里旧示范与
`runs/bc` 的旧权重是按旧配色录的，视觉分布变了，必须重录重训。**
旧权重已归档为 `runs/bc/policy_v02_yellowpads.pt`。

### 5.2 `image_size` 是裁剪，不是缩放

原来的写法：

```python
step = max(1, h // image_size)          # 160 // 96 = 1
img = img[::step, ::step][:96, :96]     # -> 就是 img[:96, :96]，裁左上角
```

`step=1` 时它取的是**左上角 96×96**，右下角直接丢掉，而且没有任何提示。
当时目标碰巧都落在左上窗口内（实测全局相机 u∈[27,55]、v∈[51,87]，v=87 已经贴边），
指标因此正常——这是靠运气。

现在训练与推理**共用** `data/preproc.py::resize_frame`（`cv2.resize`，降采样用
`INTER_AREA`），不再裁剪。两处各写一份是这类 bug 的温床：分叉之后不会报错，
只会表现为"训练指标好看、闭环失灵"。

## 6. 这些数字能说明什么、不能说明什么

**能说明**：

* 在这套观测（160² 双相机、10 Hz、3 维平移动作）与这套场景（静止或缓动的目标、
  单一颜色类别、固定支撑平面）下，**传统 CV 是最划算的解**，不需要学习；
* 闭环的价值取决于**感知系统偏差**能否被消除。这里有平面高度先验，
  所以闭环的优势被抵消了一部分；
* 单步 BC 在长视野任务上不可用（**15%**，20 回合），action chunk 的朴素实现更差。

**不能说明**：

* **不能说明 VLA 不行**。这里跑的 BC 是 1.5 M 参数的小网络、40 条示范、
  从零训练；预训练 VLA 的视觉主干与语言 grounding 是不同的量级。
* **不能证明 CV 在真实场景够用**。这里颜色干净、背景单一、光照恒定。
  换个场景（垃圾是透明的、湿的、反光的、堆叠的），颜色分割会立刻失效。
* 5 个种子的样本量只能分辨"差一个数量级"这种量级的差别，
  `cv` 与 `pbvs` 之间 2 mm 的差异**不显著**。

```bash
# 1) 重录示范（新配色）—— 40 条，约 13 分钟

# 2) 训练行为克隆（160² 输入，40 epoch，CPU 约 15 分钟）
python scripts/train_bc.py --data data/demos --out runs/bc --epochs 40 --image-size 160
python scripts/train_bc.py --data data/demos --out runs/bc_chunk8 --epochs 40 \
       --image-size 160 --chunk 8

# 3) 四方法 × 三海况 × 5 种子（约 15 分钟）
python scripts/bench_policies.py --episodes 5 --seas 0 0.35 1.0 \
       --policies expert cv pbvs bc --ckpt runs/bc/policy.pt

# 4) 只看感知精度（不跑回合）
python scripts/probe_perception.py --seeds 6
```
