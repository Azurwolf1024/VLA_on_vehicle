# 接预训练 VLA

## 1. 契约

一个策略只要满足这一件事，就能在本项目里闭环跑：

```python
action = policy.act(obs)     # obs 见 vla_vehicle.sim.env.Obs
                             # action: (4,) -> [dx,dy,dz,g] ∈ [-1,1]³ × [0,1]
```

`Obs`（全部在甲板系 / 设备坐标系）：

| 字段 | 形状 | 说明 |
|---|---|---|
| `global_rgb` | (H,W,3) uint8 | 船头相机 |
| `wrist_rgb` | (H,W,3) uint8 | 腕部相机 |
| `q`, `dq` | (7,) | 关节角、角速度 |
| `tcp` | (3,) | 末端位置 |
| `grip` | float | 归一化开口 |
| `instruction` | str | 中文或英文指令 |
| `tokens` | (L,) | 字符级 token（**预训练 VLA 不要用这个**，要自己分词） |

## 2. 三类模型要改什么

| | 行为克隆（已实现） | OpenVLA / π0 / SmolVLA | 备注 |
|---|---|---|---|
| 视觉输入 | 双相机沿通道拼成 6 通道 | 多数只吃单图 224² | 拼图或双塔，见下 |
| 语言 | 字符级 embedding | 模型自带分词器 | **必须**重新分词 |
| 动作 | 3 维平移 + 夹爪（回归） | 多为 EE delta 6-DoF + gripper，或关节角 | 需要投影到本项目动作空间 |
| 频率 | 10 Hz，单步 | 常见 action chunk (k=8~50) | 需要 chunk 队列 + 时间对齐 |
| 归一化 | 数据集统计量 | 模型自带的 q01/q99 | 两套都要，别混 |

## 2.5 本机算力与 SmallVLA 的判断（实测，不是估计）

本机是 **CPU-only**（torch CPU 版、无 CUDA）。这决定了 SmallVLA 这条路的形态：

| 环节 | 本机 CPU | 判断 |
|---|---|---|
| 单次前向（SmolVLA-450M，含 SigLIP 视觉塔） | 约 1–3 s（未测，按参数量与 CNN 实测外推） | 10 Hz 需要 0.1 s；靠 action chunk 能"跑起来"，但一次推理就吃掉 10–30 个控制周期 |
| **在本任务上微调** | 450 M × batch 8 × 上万步 | **不可行**，十几个小时起步且没有显存 |
| 显存 | 0 | 微调要 12–20 GB |

更关键的是**不微调就没有意义**：SmolVLA 的预训练数据是"头部单目 + 公开桌面场景"，
相机口径、动作空间、语言都和本项目不同。直接用必然抓空 —— 这和 BC 是同一件事，
只是模型大 300 倍。

所以要接 SmolVLA，最低条件是：单卡 ≥24 GB、CUDA 12 + PyTorch 2.x、
能访问 huggingface.co（拉 ~900 MB 权重）、能 `pip install lerobot`。

在本机已经做过的、**不需要 GPU** 的那部分：把 action chunk 的接口与数据格式打通
（`--chunk K`），并用朴素 chunk 验证了"为什么光有 chunk 不够"（见
`docs/policy_benchmark.md` §4）。这决定了上服务器之后要做的**不是**"把 BC 换成
SmolVLA"，而是"SmolVLA + temporal ensembling + 3–5 倍数据"。

## 3. 建议的接入顺序

1. **先跑通行为克隆**（`scripts/train_bc.py`）。它证明数据、动作空间、评测都自洽。
   现在的实测水平是 **15%（3/20，40 条示范、160² 输入、单步）** —— 这是
   "纯模仿学习在这条任务上的天花板"，也是判断"接 VLA 值不值"的基线。
   如果 BC 连 10% 都到不了，先查环境/数据，不要换模型。
2. **再接 VLA 的"视觉-语言编码 + 动作头"**，动作头换成 4 维回归，冻结主干微调。
   这一步能验证"预训练特征在这套相机视角下是否可用"。
3. **最后才用原生的 action chunk + 原生动作空间**，在内环加一层
   "6-DoF delta → 本项目 4 维 delta" 的投影（丢掉旋转分量或投影到 yaw-only）。

`vla_vehicle/policies/vla_adapter.py` 里 `PretrainedVLA` 就是这个接入位：
`prepare / infer / postprocess` 三个钩子，`act()` 处理 chunk 队列。
目前 `load()` 与 `infer()` 会抛 `NotImplementedError` —— 这是**故意的**，
避免出现"看起来能跑、其实没权重"的假实现。

## 4. 已知的错配（接之前先认下来）

1. **相机口径**：公开 VLA 数据集多是"头部单目 + 腕部近景"，我们的全局相机装在船头
   且随船摇动，视场里始终有一条机械臂。域差距主要来自这里。
2. **动作空间缺旋转**：v1 只有 3 维平移。抓方块/罐子够用，
   抓细长物体或需要侧向插入时不够。
3. **动力学语义**：预训练数据里"末端动 2 cm"对应的是静止基座；
   我们这里基座在动，同样的末端增量在内环里要额外补偿。别指望动作幅度能直接迁移。
4. **语言**：中文指令在英文 VLA 上基本无效。建议要么用英文指令采数据
   （`--lang en`），要么先做指令翻译再喂模型。

## 5. 评测协议（跨模型可比）

* 固定 `--seed0 1000 --episodes 20`，三档海况（`sea_calm` / 默认 / `sea_rough`）各跑一遍；
* 报 **成功率** 与 **平均步数**，同时报"抓取成功率"与"投放成功率"两个中间指标
  （需要扩展 `evaluate()`，见 `docs/roadmap.md`）；
* 与 `--policy expert`（上界）和 `--policy random`（下界）同表对照，否则数字没有意义。
