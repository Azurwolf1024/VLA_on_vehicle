# 架构

## 1. 分层

```
                      ┌──────────────────────────────────────────┐
                      │ 决策层 10 Hz   (VLA / BC / 脚本专家)      │
                      │ 输入: 全局图 + 腕部图 + 关节 + 指令        │
   obs ───────────────▶ 输出: [dx,dy,dz,g] ∈ [-1,1]³ × {0,1}      │
                      └──────────────────┬───────────────────────┘
                                         │  TCP 目标 = 指令累加 + 2 cm/步
                      ┌──────────────────▼───────────────────────┐
                      │ 内环（二选一）                            │
                      │  A. pos  100 Hz  DLS 逆解 + 关节线性插值   │
                      │  B. tsid 500 Hz  上游解析动力学 + QP      │
                      │     两者都复用 veh_arm 的 FK/Jacobian     │
                      └──────────────────┬───────────────────────┘
                         关节目标 q_des │ 或 关节力矩 τ
                      ┌──────────────────▼───────────────────────┐
                      │ 物理 500 Hz    MuJoCo mj_step             │
                      │ 载具 6-DOF 由 veh_arm.platform 逐帧写入    │
                      └──────────────────────────────────────────┘
```

三层频率不是拍脑袋定的：VLA 的推理成本决定它只能跑在 3–10 Hz；伺服与逆解需要 ≥50 Hz
才能压住船的加速度；接触稳定需要 ≥500 Hz。**任何一层改频率都不该影响另外两层的接口**，
这是数据格式（10 Hz）与动作定义（增量）能长期稳定的前提。

## 2. 关键设计决定（以及为什么）

### 2.1 动作 = 甲板系 TCP 增量，而不是关节角

* 关节角与具体臂型强绑定，换臂就得重录数据；TCP 增量与臂无关。
* VLA 拿不到可靠的关节级动力学信息，输出 7 维关节角等于让它猜逆解。
* 增量在 10 Hz 下 ±2 cm/步，对应 ≤0.2 m/s 的末端速度，正好是"能抓得准又不会撞"的区间。

代价：v1 只支持**平动**，工具姿态由内环固定成"朝下 + 指爪沿 ±y"。见 §4 的限制。

### 2.2 TCP 目标用**指令累加**，不是测量累加

`p_target = p_measured + Δ` 会在内环有稳态误差时形成棘轮：实测过"动作全零、机械臂自己爬升
2 cm/2 s"。改成 `p_cmd += Δ` 后，指令是绝对量，内环误差不会累积；只有当指令与实测偏差
超过 `resync_err`（默认 10 cm）才重新对齐。

### 2.3 载具是**运动学平台**（用 mocap，不是自由体）

vessel 是一个带 `mocap="true"` 的 body：每帧把解析出的 6-DOF 位姿写进
`data.mocap_pos/quat`，质量视为无限大 —— 接触力、机械臂的反作用力矩都推不动它。

**这里曾经是错的，代价很隐蔽**：早期版本给 vessel 挂了 `<freejoint>`，每步覆写
`qpos`，看起来"船是固定的"，但船在**每一步内部**其实都在重力下自由下落
（实测 0.1 s 掉 4.9 cm）。于是机械臂的基座一直在"下坠"，凡是假设"基座运动由外部
给定"的控制器（也就是上游 TSID 的全部前提）都对不上：给 `τ = g(q)` 做重力补偿，
臂会直接掉下去 4 rad。表现是"力矩环怎么调都不稳"，真因却在场景文件里。

改成 mocap 后同一实验的漂移从 4.34 rad 降到 0.054 rad（剩下的是关节阻尼/干摩擦）。

代价：MuJoCo 里 mocap 体速度恒为零，臂的动力学感受不到基座速度耦合项
（上游模型里有 `J_B·V_B`）。在 0.1 m/s 量级海况下这一项对应毫米级误差，
比"基座在自由落体"小两个数量级。

### 2.4 复用上游 NERO 模型：解析动力学直接当控制器

上游 `veh_arm.robot.model.Robot` 自己算 `M(q)`、`H(q,q̇,R_WB)`、`J`、`J_B`，不依赖
任何仿真器。本项目把同一份 `ArmSpec` 编译成 MJCF（`robot/mjcf.py`），于是两边
**同源**；`tests/test_dynamics.py` 再逐项验证它们确实是同一个被控对象：

| 量 | 相对误差（8 个随机位形的最差值） |
|---|---|
| `M(q)` | 4.5e-6 |
| `H = C q̇ + g` | 1.8e-6 |
| `J`（6×7，世界系） | 1.4e-7 |

唯一差异是 MuJoCo 的 `armature`（减速器折算转子惯量 0.02）——上游没有这个字段。
腕部三关节连杆惯量只有 1e-3 量级，忽略它等于把腕部惯量算小 20 倍。

**所以 NERO 的模型在 MuJoCo 里不是"能用"，而是"就是它"**：
`control/tsid.py` 把 `TSIDController` 原样接上，MuJoCo 只负责接触与积分。

两处必须在适配器里处理、且不能悄悄改上游的地方：

1. **转子惯量要进 QP，不能事后补**。先算 `τ` 再补 `A·q̈`，QP 的力矩约束用的还是
   不含 A 的 `M`，会批准一个实际超限的解（实测关节 4 要 47 N·m、上限 40），
   电机一饱和环路就进极限环。这里用 `_ArmatureRobot` 包一层，让 QP 看到真实的 M。
2. **TCP ≠ 法兰**。上游 `ee_pose` 给的是法兰，本项目任务目标是 TCP（法兰 +105 mm）。
   不换基等于让控制器去追一个偏出 10 cm 的虚点。

`Kp/Kd` 用的是 2000/80 而不是论文 Table I 的 500/40：那组增益是按论文那台臂与
它的任务调的，在本环境里 500/40 会让 TCP 稳态落后 3 cm，抓取阶段直接压在物体顶上。
这一条属于**调参**，不是模型差异，写在 `TSIDConfig` 的 docstring 里。

### 2.5 垃圾是**独立自由体**，不挂在船上

靠摩擦被甲板带着走。这样"甲板在动"是真的在动，物体也会滑动/翻倒 —— 这是真实失效模式，
也是后续"抗扰动抓取"要研究的东西。代价：必须保证船速不会把物体冲走（见 `docs/sim.md`）。

### 2.6 抓取用运动学吸附（`grasp_mode="attach"`）

夹爪闭合到位后，物体每个物理子步被写成"工具位姿 ⊗ 抓住瞬间的相对位姿"。
不用纯接触摩擦的理由写在 `docs/sim.md` §5（实测滑移 40–180 mm，是 MuJoCo 里
"轻物体被重手抓"的典型病态）。这条替代方案在 RoboSuite / Meta-World 里也很常见。

**它影响什么**：抓取成功与否只取决于接近位姿，不取决于接触力调参 —— 这对数据质量是好事。
**它不影响什么**：释放、下落、落点、碰撞都还是真物理。

## 3. 坐标系

| 坐标系 | 定义 | 谁在用 |
|---|---|---|
| 世界系 | 水面 z=0，原点为初始船位 | 渲染、可视化 |
| **甲板系** | 原点在甲板面机械臂安装点，+x 船头，+z 向上 | 机械臂 FK/IK、动作、垃圾与舱位、物体位姿 |
| 工具系 | 法兰 + 沿法兰法向 0.105 m | 夹爪几何、腕部相机 |
| 相机系 | MuJoCo 约定：视线 -z，上 +y | 图像 |

所有策略能看到的位置量都在**甲板系**：船在动的时候，"物体在甲板系里的位置"才是
闭环控制该跟踪的东西（世界系定点是另一个任务，见 `docs/roadmap.md`）。

## 4. 限制（第一版明确不做）

1. **没有旋转动作**：抓取姿态恒为朝下。细长物体、需要侧抓/插孔的任务做不了。
2. **世界系定点只是能力演示，不是任务配置**：`control_mode="tsid"` + `frame="world"`
   能真的把末端钉在世界上（见 `docs/control.md`），但目标不随船走意味着甲板上的
   物体会漂出夹爪，所以抓放任务仍然只能定义在甲板系。
3. **末端状态估计没接**：仿真里直接把真值 `R_WB/p_B/ω/v/α/a` 喂给控制器。
   真机上游走 ESKF，噪声与滞后都会进来。
4. **没有真机**：`veh_arm` 提供 `veh_arm_ctl` 的部署层，接 NERO 实机时
   替换 `PickPlaceEnv` 的 `step()` 即可，数据格式不变。
5. **语言是字符级 token**，不是预训练 VLA 的分词器；接预训练模型时必须重新分词。
